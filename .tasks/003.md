A part writes down what it put on the machine. One part can then be updated or removed without touching another's files, and removing everything is the sum of the records.

On record: the org-harness repo fell behind the mini because tools were edited on the box, and a deploy would now roll the server back (its T91). The fellows' kit removes only what it can prove it installed.

Question 1: should clv update only bring the tool up to date and say what changed, with each part re-running its own setup only when that setup changed? Levi 10/3, relayed by the coordinating session: "why would an update always run the installer? seems weird to me."

Question 2: when someone leaves, what should one command remove from their laptop, and what should stay? Levi 10/3, relayed: "is that the durable shape though? to have the uninstall not be a full uninstall?"

Done when: with two parts installed, removing one leaves every file of the other in place, and updating the tool changes no part's setup unless that part's own setup changed.

Intent: update and uninstall do what their names say, part by part (the two questions Levi raised 10/3).
